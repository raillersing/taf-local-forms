Guide formateur · Avant la séance

Démarrer l’application sans stress.

Fais les étapes dans l’ordre. Quand tu vois « OK », passe à l’étape suivante. Les élèves utilisent ensuite l’adresse de l’IP du laptop avec le port 8011.

Contrôler le réseau Retour au cockpit
5étapesEnviron 2 minutes
Composant 1 · Dans Docker

L’application web

Django, les questionnaires, le cockpit et la base de données tournent dans les conteneurs Docker.

Adresse formateur : http://localhost:8010/

Composant 2 · Hors Docker

Le helper Windows

Le script PowerShell est fourni dans le dépôt, mais il doit être exécuté directement par Windows pour gérer le pare-feu et le portproxy.

Adresse locale : 127.0.0.1:8019

Il ne faut pas chercher le helper dans l’interface Docker : il est lancé séparément, une fois par session Windows.

Avant de commencer

  • Le laptop est connecté au Wi-Fi ou au hotspot de la classe.
  • Docker Desktop est démarré et l’intégration WSL est active.
  • Les téléphones des élèves pourront rejoindre le même réseau local.
Important : ne partage jamais localhost avec les élèves. Cette adresse fonctionne uniquement sur le laptop formateur.
01

Démarrer Docker

Dans Ubuntu/WSL, place-toi dans le dépôt du projet et démarre l’application.

docker compose up -d

Puis ouvre http://localhost:8010/.

✓ La page d’accueil doit s’afficher.
02

Ouvrir le cockpit

Connecte-toi avec ton compte formateur. Le cockpit est réservé au formateur.

Ouvrir le cockpit
03

Démarrer le helper Windows

Le helper est dans le dépôt, mais il s’exécute hors de Docker. Il permet de vérifier l’IP, le portproxy et le pare-feu Windows.

.\scripts\windows\taf-lan-helper-start.ps1
  1. Ouvre PowerShell en administrateur — nécessaire pour le pare-feu et le portproxy.
  2. Place-toi dans le dépôt.
  3. Exécute la commande.
✓ Le helper écoute sur 127.0.0.1:8019.
04

Préparer l’accès élèves

Dans le contrôle LAN, clique sur Préparer la séance, puis sur Tester l’URL élèves.

Préparer la séance

Vérifie l’IP réelle, le portproxy, le pare-feu et l’URL élèves.

05 · Vérification finale

Tester avec un vrai téléphone

Connecte un téléphone au même Wi-Fi ou hotspot que le laptop, puis ouvre l’URL affichée :

http://IP_DU_LAPTOP:8011/

  • La page d’accueil s’ouvre.
  • Un module s’ouvre correctement.
  • Coche ensuite « Test téléphone réel » dans la page Réseau.
Ouvrir la page RéseauOuvrir la projection
Si quelque chose ne marche pas

Diagnostic rapide

  • Page locale absente : vérifie Docker avec docker compose ps.
  • Helper absent : relance PowerShell en administrateur.
  • Téléphone inaccessible : vérifie le même Wi-Fi, l’IP, le port 8011 et le pare-feu.
  • IP changée : clique sur « Préparer la séance » avant de partager une nouvelle URL.
